====================================================================================================
                             JAA BACKEND - COMPLETE REST API SPECIFICATION
====================================================================================================
Base URL:          http://localhost:5000/api  (or http://localhost:5000)
Server Health:     http://localhost:5000/health
Documentation:     http://localhost:5000/api
Date/Time Format:  All "createdAt" and "updatedAt" fields return formatted as: "DD-MM-YYYY hh:mm am/pm"
                   (Example: "21-10-2026 05:14 pm" in Asia/Kolkata Indian Standard Time)
                   Date fields like "joinedOn" and "createdOn" return formatted as: "DD-MM-YYYY"
                   (Example: "23-10-2026")
Sort Order:        All listing APIs return data in DESCENDING order (newest posted data first: { id: -1 })
Supported Encodings: application/json, multipart/form-data, application/x-www-form-urlencoded
Authentication:    Bearer Token ("Authorization: Bearer <token>") OR Cookie ("token" / "accessToken")
Mock Dev Token:    "mock-jwt-token-JAA-admin" (auto-authenticates as admin in dev)
Sequential IDs:    All models have atomic numeric IDs: 1, 2, 3, 4, ...

[2.5] Change Password
--------------------------------------------------
Method:      POST
Endpoint:    /api/change-password  (or /api/auth/change-password, or camelCase: /api/changePassword)
Headers:     Content-Type: application/json or multipart/form-data
Auth:        Bearer Token (optional if session/payload identifies user)

Request Body:
{
  "currentPassword": "OldPassword@123",       // (Required) String (also accepts alias "oldPassword")
  "newPassword": "NewPassword@123",           // (Required) String
  "confirmNewPassword": "NewPassword@123"     // (Required) String (also accepts alias "confirmPassword")
}

Responses:
- Success (200 OK):
  {
    "success": true,
    "message": "Password changed successfully."
  }

- If Current Password is Incorrect (400 Bad Request):
  {
    "success": false,
    "message": "Current password is incorrect."
  }

- If New Passwords Do Not Match (400 Bad Request):
  {
    "success": false,
    "message": "New password and confirm password do not match."
  }

[10.1] Get Posts List
--------------------------------------------------
Method:      GET
Endpoints:   /api/admin/posts  or  /api/posts
Query Params:
  - search:     Search string (matches title, description, location, admin name/email, member name/business)
  - mediaType:  'Photo' | 'Video' | 'Notice' | 'all'
  - location:   Filter by location (e.g. 'Ahmedabad')
  - isPinned:   true | false | 'all'
  - status:     'published' | 'draft' | 'all'
  - page:       Page number (default: 1)
  - limit:      Items per page (default: 20)

Note: In the list endpoint, each post contains only the index [0] media item, postedBy snapshot, createdAt, and status. Full post details are available via GET /api/admin/posts/:id.

13. COMMON RESPONSE & ERROR FORMATS
====================================================================================================

[13.1] Standard Success Envelope (used across endpoints)
--------------------------------------------------
HTTP Status: 200 OK (or 201 Created)
{
  "success": true,
  "message": "Resource retrieved / operation successful",
  "data": { ... },
  "pagination": {
    "total": 100,
    "page": 1,
    "limit": 20,
    "totalPages": 7,
    "hasNext": true,
    "hasPrev": false
  }
}

[13.2] Standard Error Envelope (Operational errors)
--------------------------------------------------
HTTP Status: 400 Bad Request / 401 Unauthorized / 403 Forbidden / 404 Not Found / 409 Conflict / 500 Internal Error
{
  "success": false,
  "message": "Human readable error message",
  "errors": []  // (Optional array if specific validation issues exist)
}

[13.3] Validation Error Envelope (Zod schema failure - 422 Unprocessable)
--------------------------------------------------
HTTP Status: 422 Unprocessable Entity
{
  "success": false,
  "message": "Valid email address is required",
  "errors": [
    {
      "field": "email",
      "message": "Valid email address is required"
    }
  ]
}
