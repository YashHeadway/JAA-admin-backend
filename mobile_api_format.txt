====================================================================================================
               JAA MOBILE APP - MEMBER AUTHENTICATION & PROFILE REST API SPECIFICATION
====================================================================================================
Base URL:          http://localhost:5000/api  (or http://192.168.1.26:5000/api)
Route Group:       /api/members/*  (also available at /api/member/*)
Discovery:         GET /api (contains userRoutes.auth)
Supported Encoding: application/json, multipart/form-data, application/x-www-form-urlencoded
Authentication:    Bearer Token ("Authorization: Bearer <token>") OR Cookie ("token")
Token Placement:   In all authentication responses, "token" is returned at the very end of the JSON object.
====================================================================================================

2. MEMBER REGISTER (MOBILE SIGN UP)
====================================================================================================

Method:      POST
Endpoint:    /api/members/register  (also: /api/member/register, /api/members/signup)
Headers:     Content-Type: application/json or multipart/form-data
Auth:        None (Public)
Description: Creates a User account (role: Member) and a Member entry (status: pending).
             Returns the member data and authenticates the user with a JWT token (token is last).

Request Body (Exact fields matching Mobile UI screen + Required Password):
{
  "fullName": "Pooja Sharma",                 // (Required) String - Full Name (or "name")
  "businessName": "Sharma Art Jewellers",     // (Required) String - Business Name (or "business")
  "businessType": "Retailer",                 // (Optional) String - Dropdown (default: 'Retailer')
  "email": "pooja.sharma@example.com",        // (Required) String - Email Address (used for login)
  "mobile": "9825123456",                     // (Required) String - Mobile Number (or "phone")
  "city": "Ahmedabad",                        // (Optional) String - City (default: 'Ahmedabad')
  "password": "password123",                  // (Required) String - Min 6 chars (strictly required for login)
  "confirmPassword": "password123"            // (Optional) String - Must match password if provided
}

Note: The "password" field is STRICTLY REQUIRED on member registration. Without it, the API rejects the request with HTTP 400 ("Password is required and must be at least 6 characters"). Additional optional fields like "avatar", "address", "pincode", "dob" are also supported.

4. MEMBER FORGOT PASSWORD
====================================================================================================

Method:      POST
Endpoint:    /api/members/forgot-password  (also: /api/members/forget-password)
Headers:     Content-Type: application/json or multipart/form-data
Auth:        None (Public)
Description: Generates a 1-hour secure reset token and sends a password reset email to the member.
             In development mode, "resetToken" is included in response for easy testing.

Request Body (Option A - By Email):
{
  "email": "pooja.sharma@example.com"
}

Request Body (Option B - By Mobile):
{
  "mobile": "9825123456"
}

Response (200 OK):
{
  "success": true,
  "message": "If an account exists with this email, a password reset link will be sent.",
  "resetToken": "a1b2c3d4e5f6..."
}


====================================================================================================
5. MEMBER RESET PASSWORD
====================================================================================================

Method:      POST
Endpoint:    /api/members/reset-password  (also: /api/member/reset-password)
Headers:     Content-Type: application/json or multipart/form-data
Auth:        None (Public with token)
Description: Sets a new password using the reset token obtained from forgot-password.

Request Body:
{
  "token": "a1b2c3d4e5f6...",                 // (Required) String - Reset token
  "newPassword": "newSecretPassword123",      // (Required) String - Min 6 chars
  "confirmPassword": "newSecretPassword123",  // (Required) String - Must match newPassword
  "email": "pooja.sharma@example.com"         // (Optional) String
}

Response (200 OK):
{
  "success": true,
  "message": "Password reset successfully."
}

Error Responses:
- 400 Bad Request: { "success": false, "message": "Invalid or expired password reset token." }
- 400 Bad Request: { "success": false, "message": "New password and confirm password do not match." }


====================================================================================================
6. MEMBER CHANGE PASSWORD
====================================================================================================

Method:      POST
Endpoint:    /api/members/change-password  (also: /api/member/change-password)
Headers:     Content-Type: application/json or multipart/form-data
             Authorization: Bearer <token>
Auth:        Required (Authenticated Member)
Description: Allows an authenticated member to change their current password.

Request Body:
{
  "currentPassword": "password123",           // (Required) String - Current valid password
  "newPassword": "myNewStrongPassword456",    // (Required) String - Min 6 chars
  "confirmPassword": "myNewStrongPassword456" // (Required) String - Must match newPassword
}

Response (200 OK):
{
  "success": true,
  "message": "Password changed successfully."
}

Error Responses:
- 400 Bad Request:  { "success": false, "message": "Current password is incorrect." }
- 400 Bad Request:  { "success": false, "message": "New password and confirm password do not match." }
- 401 Unauthorized: { "success": false, "message": "Authentication required" }

9. MEMBER LOGOUT
====================================================================================================

Method:      POST  (also accepts GET)
Endpoint:    /api/members/logout  (also: /api/member/logout, /api/logout)
Headers:     Authorization: Bearer <token> (optional)
Auth:        None / Optional
Description: Revokes the member's JWT token in TokenBlacklist and clears authentication cookies.
             Always returns 200 OK. Subsequent attempts to call protected member routes with the old
             token return 401 Unauthorized.

Response (200 OK):
{
  "success": true,
  "message": "Logout successful"
}
